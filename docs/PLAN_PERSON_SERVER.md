# 方案 A · 服务器预计算 · 场上人物检测与稳定 ID 跟踪

> 版本 v0.1（2026-10-18）· 对应需求：854×356 俯拍夜景五人场，**5 秒片段内 ≥85% 帧判对**（帧级口径，定义见 [`EVAL_PERSON.md`](EVAL_PERSON.md)）。
> 定位：与 BallTracer（球轨迹预计算）同构的 **PC/服务器侧离线管线**，产出 `tracks_person.json` 推送端侧回放/跟焦。

---

## 1. 结论先行

| 项 | 结论 |
|---|---|
| 可达性 | **帧级 85% 可达**。人框高 28~99px（中位 35~52px），比球（3~8px）大一个量级，本项目最难的球检测已做到 85%+，人物检测难度低于球 |
| 核心手段 | 领域微调（COCO 裸模型不够）+ imgsz=1280 级分辨率 + ByteTrack 低分二关联 + 场地 ROI 掩膜 |
| 复用资产 | 评审闭环（review_gallery.html）、负样本挖掘套路（build_neg.py）、I/P 帧分区思想、MPEG 式切片、 BallTracer 的门限/插值参数体系 |
| 主要风险 | 广告牌海报人物误检（已实测出现）→ ROI 掩膜 + 负样本微调；密集遮挡 ID 切换 → ReID 后处理 |
| 工期 | 约 4~5 个工作日（标注 2d → 微调 0.5d → 管线 1d → 评测迭代 1d） |

## 2. 实测依据（2026-10-18，yolo26n COCO 裸模型，full.mp4）

用 `weights/yolo26n.pt`（COCO 预训练，未微调）在 segs_cur.json 5 个代表段上实测：

| 段 | 机位 | 人数/帧 (imgsz=640) | 人数/帧 (imgsz=1280) | 框高中位 | conf 中位 (640→1280) |
|---|---|---|---|---|---|
| s0 | M c 中景 | 7.6 | 11.2 | 42px | 0.51 → 0.53 |
| s2 | V a g 近景 | 8.1 | 11.6 | 52px | 0.58 → 0.66 |
| s5 | V dr | 9.2 | — | 49px | 0.55 |
| s12 | M c | 9.4 | — | 50px | 0.50 |
| s29 | M p 远景 | 7.3 | 11.1 | 35px | 0.35 → **0.47** |

目检图（仓库外，`../../probe_person_s29_f60.jpg`、`../../probe_person_s0_f80.jpg`、`../../probe_person_s2_f100.jpg`）确认三个事实：

1. **imgsz=1280 多检出的是真人**（远景小人、密集人群），人数 7.3→11.1，与"五人场 = 10 球员 + 裁判"吻合——即 **imgsz=640 系统性漏检约 35%**；
2. imgsz=1280 同时**引入广告牌海报人物误检**（conf 最高到 0.63）；
3. 各段零检出帧 = 0，漏检是"个体级"而非"整帧级"——ByteTrack 的低分二关联正好对症。

**推论**：
- 分辨率是第一杠杆；上采样本身无效（up=2 + imgsz=640 与 1x 完全一样，YOLO 内部又缩回去了），**必须提高推理分辨率或切片**；
- COCO 裸模型 conf 中位 0.34~0.58、≥0.5 帧占比仅 25~60% → **领域微调是必选项**，不是可选项（与 README §2 教训 #6「人框检出不稳」一致）；
- 误检集中在场地外（广告牌/看台），固定机位 → ROI 掩膜可一劳永逸。

## 3. 管线架构

```
full.mp4 (854×356, 29.97fps)
   │
   ├─① person 检测（领域微调 yolo11n，imgsz=1280）
   │     conf=0.10 低阈采集（复用球管线 CONF=0.03 思想，后级过滤）
   │     → dets_person/<si>.json  [{f, t, ppl:[{x,y,w,h,conf}]}]
   │
   ├─② ROI 掩膜过滤（每机位 M/V 标一次场地多边形，框心在多边形外直接丢弃）
   │     → 消除广告牌/看台/观众误检（实测误检全部在 ROI 外）
   │
   ├─③ ByteTrack 多目标跟踪（低分二关联，恢复"个体级漏检"）
   │     track_high_thresh=0.35 / track_low_thresh=0.10 / new_track_thresh=0.45
   │     → 每帧每人 {track_id, box}
   │
   ├─④ 离线全局修正（服务器独有优势：可用未来帧）
   │     a. 轨迹双向插值补漏（≤15 帧，复用 BallTracer FILL_MAX/smoothstep）
   │     b. ID 一致化：跨遮挡断链再连——球衣颜色直方图 + 位置-速度门限，
   │        同机位下颜色特征极稳（固定机位、灯光恒定）
   │     c. 幽灵轨迹清理（<20 帧且无高置信帧的短链丢弃）
   │
   └─⑤ 输出 tracks_person.json（与 BallTracer 轨迹同帧号对齐，可合并下发）
         {seg_id, fps, frames:[{f, ppl:[{id, x,y,w,h, conf}]}]}
```

### 3.1 检测层：微调 yolo11n（person 单类）

| 项 | 取值 | 依据 |
|---|---|---|
| 基座 | `yolo11n.pt`（与球模型同家族，train_ball.py 直接改类别数） | 管线复用 |
| 输入 | imgsz=1280 全帧（不切片） | §2：1280 召回 +52%；服务器算力无忧；球走 SAHI 切片是因为球 3~8px，人 35~52px 用 1280 全帧已够 |
| 类别 | person 单类（球检测继续走 BallTracer，两管线解耦） | 解耦后互不拖累 |
| 训练 | 60 ep，batch=6，RTX 5070 Ti，~40min（train_ball.py 改类别） | 已验证流程 |

### 3.2 数据与标注闭环（复用评审闭环，成本可控）

```
imgsz=1280 COCO 裸模型伪标签（conf≥0.30，ROI 内）
      ▼  32 段 × 每 3 帧 1 张 ≈ 960 帧、约 9000 框
review_gallery.html 人工修正（现成工具：增/删/改框，导出 JSON）
      ▼  按段切分：s2/s3/s6/s10/s12/s13/s20/s23/s29 等 20 段训练，
         s0/s5/s7 等留作验证；5s 评测片段另抽（见 EVAL_PERSON.md）
build_dataset_person.py → dataset_person/（train/val）
      ▼
train_person.py（yolo11n，60 ep）
      ▼
误检回归：广告牌/看台区域挖 FP（build_neg.py 套路）→ 硬负样本 → 续训 20 ep
      ▼ 不达标回到伪标签修正步迭代
```

标注量估计：960 帧中人工实际改动预计 20~30%（伪标签基线已可用），约 1.5~2 个工作日。

### 3.3 跟踪层参数（ByteTrack 默认起步，按本域调）

| 参数 | 起始值 | 说明 |
|---|---|---|
| track_high_thresh | 0.35 | 高分首关联（微调后 conf 分布上移，无需 0.5） |
| track_low_thresh | 0.10 | 低分二关联——专治"个体级漏检"（§2 事实 3） |
| new_track_thresh | 0.45 | 新轨迹门槛，压幽灵链 |
| match_thresh | 0.80 | IoU 关联阈值 |
| 断链保留 | 30 帧 | 五人场遮挡通常 <1s |

### 3.4 离线修正（方案 A 相对端侧的精度来源）

- **双向信息**：离线可看未来帧。断链两端若颜色直方图距离 < 阈值且位置-速度外推吻合 → 重新接 ID；
- **插值**：空洞 ≤15 帧用 smoothstep 补框（尺寸同步插值），>15 帧诚实留空（宁缺勿错，与球管线同一哲学）；
- **全局 ID 校验**：同一 5s 片段内某 track 的颜色直方图若分裂为两个簇 → 报告为可疑 ID switch，进人工抽查队列。

## 4. 算力与耗时预算（RTX 5070 Ti）

| 步骤 | 单帧成本 | 90 分钟视频（~162k 帧） |
|---|---|---|
| yolo11n imgsz=1280 推理 | ~8 ms | ~22 min |
| ByteTrack | <1 ms | ~3 min |

| **合计** | | **~30 min/场**，可行；后续接 I/P 帧分区（每 3 帧全检 + 中间帧 ROI）可再省 ~40%，与 BallTracer 同套路 |

## 5. 风险与对策

| 风险 | 证据 | 对策 |
|---|---|---|
| 广告牌海报人物误检 | §2 目检：conf 最高 0.63 | ROI 多边形掩膜（一劳永逸）+ 海报区域硬负样本微调（球项目 FP/TP 3.99→0.76 已验证此套路） |
| 密集遮挡 ID 切换 | 人数 8~11/帧，俯拍下人挨人 | ByteTrack 二关联 + 颜色直方图 ReID 重连 + IDF1 监控 |
| 远景小人召回不足 | s29 conf 中位仅 0.47@1280 | 远景段评测单独看；不足则对远景加 2 切片推理（服务器算力允许），同球管线「降阈冷启动 + 严门限」思想 |
| 俯拍框只到膝盖（README 教训 #6） | COCO 域差 | 微调数据本身来自本域伪标签+人工修正，天然对齐；标注规范里明确"框到可见最低点" |
| 换机位/换场地泛化 | README 已知限制 | 评测协议含未训练段（s10/s12/s13/s20/s23/s29）；新机位需重标 ROI + 增量微调 |

## 6. 验收与里程碑

验收口径以 [`EVAL_PERSON.md`](EVAL_PERSON.md) 为准：**32 个 5 秒片段，片段内 ≥85% 帧判对；20 个片段通过即为达标**（留 12 个给端侧方案压力分布）。

| 里程碑 | 内容 | 工期 |
|---|---|---|
| M1 | 伪标签 + 人工修正完成，dataset_person 就绪 | 2d |
| M2 | person 微调模型 val mAP50 ≥ 0.90 | 0.5d |
| M3 | ByteTrack + 离线修正管线跑通，出标注视频抽查 | 1d |
| M4 | 评测达标（FrameAcc ≥ 85%），交付 tracks_person.json | 1~1.5d |

M4 未达标时的降级路径（按优先级）：
1. 漏检为主 → 远景切片推理 / 训练加 150ep；
2. 误检为主 → 负样本再挖一轮 + conf 门槛上调；
3. ID 切换为主 → 颜色 ReID 权重调高、断链保留延长到 45 帧。
