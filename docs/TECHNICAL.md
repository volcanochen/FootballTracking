# BallTracer 技术细节文档

> 名称：**BallTracer**（足踪 · 足球轨迹预计算引擎）
> 版本：**v1.0.0**（2026-10-18）
> 定位：PC / 服务器侧预计算「球在哪」，为端侧跟焦放大镜提供轨迹数据。
> 源视频约束：854×356 低清、固定俯拍机位、29.97 fps 的夜景五人场录像。

---

## 1. 问题约束

| 约束 | 数值 / 说明 | 对方案的影响 |
|---|---|---|
| 画质 | 854×356（检测用 2x=1708×712） | 球仅占 3~8 px，常规全帧检测几乎无效 |
| 球色 | 白球，低对比（草皮/灯光） | 需要针对白球做领域微调 |
| 运动 | 单球、高速、频繁遮挡/出框 | 不能依赖每帧检出，需时序补全 |
| 机位 | 固定俯拍，无镜头切换 | 可用「切片 + ROI」做分区识别（类 MPEG） |
| 产物 | 轨迹 JSON / 标注视频，推送到手机回放 | 离线预计算，非端侧实时 |

**核心设计原则（与需求方确认）**：场上只有一个球；高置信锁定后只考虑相邻位置的候选；高速/遮挡时单帧不可判 → 不强求每帧检出，关键帧找对即可，中间按物理规律补轨迹。

---

## 2. 整体管线

```
full.mp4
   │  collect_candidates()   # MPEG 式分区识别
   ▼
cand_s{id}.json  [{f, d:[[x,y,w,h,conf],...]}]
   │  build_track()         # 双向时序门限 + 跳变清理 + 插值
   ▼
track / fills / rejected
   │  draw_video()          # 标注视频
   ▼
model_track_v2_s{id}[_i{init}].mp4
```

三步完全解耦、可独立重跑；候选采集为最重的 GPU 步骤，结果缓存到 JSON 后，跟踪与标注阶段为零 GPU 迭代。

## 3. 检测：SAHI 切片 + MPEG 式 I/P 帧

### 3.1 为什么切片
低清画面里球只有 3~8 px，直接 `imgsz=1280` 全帧推理会把球缩到不可见。**SAHI 式横向切片**（3 列、重叠 0.20）把局部放大后检测，召回显著上升。经验证：3x 放大、imgsz=1536、NX=4 等方案均无效——**训练与推理必须同域**（本方案自始至终在 854×356 / 2x 域）。

### 3.2 三模型融合（候选级）
每帧候选由三个模型并集、按中心距 NMS 合并：
- `ball_tile_v3`（切片域最终模型，SAHI 切片推理）
- `ball11n_vb`（YOLO11n 全帧，COCO 微调后领域重训 150 ep，基线）
- `ball11n`（旧全帧基线）

### 3.3 MPEG 式 I/P 帧分区识别
- **I 帧**（每 `KEY_EVERY=3` 帧，或链未建立时）：全画面 = 切片 3 分区 + 全帧 vb + 全帧 old（5 次推理）。
- **P 帧**：仅对「上一帧预测位置所在分区」做切片 + 全帧 vb（2 次推理），检出仅作候选。
- 收益：相比全帧每帧 5 推，省约 40% 算力；P 帧 ROI 选取依赖前帧粗预测，精确门限仍在后级。

> 注意：P 帧靠 `cv2` 顺序读帧，避免反复 `cap.set` seek 导致的帧错位（早期邻帧融合掉分正是 seek bug 假象）。

## 4. 时序跟踪：物理速度门限 + 跳变清理 + 插值

### 4.1 双向门限（`run_pass`）
从任意高置信帧（`INIT_CONF=0.30`）起链，沿时间正向、反向各跑一遍：
- 预测位置 `p' = p + v`，门限 `R = min(GATE_MAX, GATE_BASE + GATE_V·|v| + RECAP_STEP·lost)`。
- 在 `R` 内取最近候选；否则速度衰减、丢失计数 +1，超过 `MAXLOST=25` 重置链。
- 正向/反向并集缝合，覆盖率高于单向。

### 4.2 物理速度硬约束（解决「不可能跳变」）
- `GATE_MAX=0.04` 画面宽/帧：实测球速 p95≈0.016/帧，留 2.5× 余量。原 `0.07/帧` 过松，正是长距跳变成因。
- **链路级跳变清理**：缝合后扫描相邻帧位移，若 `dist > JUMP_HARD(0.06)·Δ帧` 视为不可能跳变，剔除低置信端。

### 4.3 插值补帧（`FILL_MAX=15`）
相邻确定帧间隙 ≤15 帧且间隙平均速度不超 `JUMP_HARD`，用平滑插值（smoothstep）补出轨迹点，标注为橙色 `pred`。

### 4.4 标注图例
- **红框 + `ball x.xx`**：门限内检出（含 conf）
- **橙框 + `pred`**：插值补全
- **灰虚线**：双向均拒的突现检出（疑似误检）
- **绿点尾巴**：最近 18 帧轨迹

## 5. 专项修正

### 5.1 禁区线误检（负样本）
`mine_fp.py` 量化误检热点集中在远处禁区区（y≈0.29，x≈0.19~0.35），FP/TP=3.99@conf0.05。
`build_neg.py` 据此生成 210 帧×3 切片、共 601 个空标签负样本，微调 `ball_tile_v3` 40 ep → **FP/TP 降至 0.76（降 5 倍）**。

### 5.2 远景弱信号（降阈冷启动）
远景端球像素极小，置信峰值仅 0.22~0.30，低于 `INIT_CONF` 导致整段空输出。CLI `--init-conf` 可调低（如 0.12）以召回，配合物理门限仍能有效剔除噪声（见 §7 泛化测试 s29）。

## 6. 指标

### 6.1 种子帧评测（181 个人工锚点帧）
- 单帧检测上限约 79%（38 帧无任何模型信号，属物理不可见）。
- 长时轴邻帧融合（t±1，decay 0.6）：`R=0.035 → 85.1%（154/181）`；`R=0.04 → 86.7%`。
- 分段召回：s2 96% / s4 100% / s6 100% / s3 81% / s7 83% / s0 56% / s5 69%（s0/s5 为剧烈模糊极限段）。
- FP/TP：3.99 → 0.76。

### 6.2 视频覆盖（标注视频内）
检出帧 + 插值帧构成覆盖；空隙为无信号/超门限拒检。代表段：s2 100%、s6 100%、s4 92%。

## 7. 泛化测试（其他画面稳定性）

用 `segs_cur.json` 中**未参与训练/评测**的 6 段（s10/s12/s13/s20/s23/s29，覆盖全场 17~89 min、M/V 两种机位）跑同一管线：

| 段 | 机位 | 直接检出 | 插值 | 结论 |
|---|---|---|---|---|
| s12 | M 中近景 | 60% | 81 | 稳定，抽查真阳性 |
| s13 | V 进攻 | 67% | 16 | 稳定，抽查真阳性 |
| s10 | V 进攻 | 28% | 67 | 稳定 |
| s20 | M 中近景 | 27% | 46 | 稳定（少量远拒） |
| s29 | M 远景 | 0%（标准阈）→ 22%（init 0.12） | 36 | 远景弱信号，降阈后物理连续 |
| s23 | V 远景 | 0%（标准阈）→ 6%（init 0.12） | 10 | 远景 + 噪声，基本不可用 |

**结论**：同机位、常规距离下识别稳定，与原 8 段同水平，无误检爆炸或轨迹乱跳；唯一系统性薄弱点是**球场远端小球**（约 3~8 px），需更多远距样本或自适应降阈。

## 8. 用法

### 命令行
```bash
python -m balltracer \
  --video full.mp4 \
  --segs segs_cur.json \
  --seg-ids 0,1,2,3,4,5,6,7 \
  --tile-weights runs/ball_tile_v3/weights/best.pt \
  --init-conf 0.30          # 远景弱信号可调到 0.12
```
`--seg-ids all` 处理全部段；候选缓存于 `cand_s{id}.json`，重跑跟踪/标注无需 GPU。

### Python API
```python
from balltracer import run
stats = run("full.mp4", "segs_cur.json", "12", tile_weights="runs/ball_tile_v3/weights/best.pt")
# 或分步：collect_candidates() -> build_track() -> load_cands()/draw_video()
```

## 9. 已知限制与后续

1. **域绑定强**：仅在 854×356 / 2x 俯拍夜景域验证；换分辨率/机位需重训切片模型（同域原则）。
2. **远景小球**：置信度不足，依赖降阈冷启动，仍有漏检。方向：挖远景难例微调、或加自适应降阈（低置信冷启动 + 更严时序校验）。
3. **实时性**：YOLO11n 约 2.6M 参数，旗舰机 NCNN int8 imgsz=1280 约 5~10 fps 勉强；本项目定位 **PC 预计算轨迹 → 推送手机回放**，端侧仅做因果单向门限版实时。
4. **权重与视频不随仓库分发**（项目规则），见 `.gitignore`。
