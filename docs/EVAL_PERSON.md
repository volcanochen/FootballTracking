# 评测协议 · 人物检测跟踪 85%/5s（方案 A/B 共用）

> 版本 v0.1（2026-10-18）。两套方案必须用同一把尺子，避免各说各话。

## 1. 评测片段

- 从 `segs_cur.json` 的 32 段中，每段取**中间连续 5 秒**（29.97fps ≈ 150 帧），共 32 个评测片段；
- 另取 6 个未参与训练的段（s10/s12/s13/s20/s23/s29）同法各取 1 个，作**泛化组**单独报告；
- 训练用帧与评测片段**按段隔离**：某段一旦进入评测集，其全部帧不进训练集。

## 2. 真值标注

- 每 3 帧标 1 张（50 帧/片段 × 38 片段 ≈ 1900 帧、约 2 万人框）；
- 标注对象：场地 ROI 内、可见高度 ≥20px 的人（球员 + 裁判）；广告牌海报/看台观众**不标**；
- 框规范：贴合可见人体（俯拍下框到可见最低点，允许只到膝盖）；
- 工具：复用 `review_gallery.html` 评审闭环，伪标签预填 + 人工修正；
- 遮挡判定：≥50% 可见才要求检出，<50% 可见帧不计入该目标。

## 3. 「帧判对」定义（帧级 85% 的分母与分子）

一帧判对，需同时满足：

1. **检出**：每个应检出 GT 框都被某条输出轨迹以 IoU ≥ 0.5 覆盖（遮挡 <50% 的目标除外）；
2. **跟踪**：每条覆盖轨迹的 ID 与该目标在**本片段首帧**的 ID 一致；一个 GT 目标被两条以上轨迹同时覆盖视为错；
3. **误检**：IoU < 0.3 且不覆盖任何 GT 的输出框 ≤ 1 个/帧（场地 ROI 外的输出框一律计入误检）。

片段通过 = 片段内 ≥85%（≥128/150）帧判对。
**总达标线：评测组 32 片段中 ≥20 个通过，且泛化组 6 片段中 ≥3 个通过。**

## 4. 辅助指标（诊断用，不作达标线）

| 指标 | 用途 |
|---|---|
| MOTA / IDF1 / IDSW | MOT 标准指标，定位"检出问题 vs ID 问题" |
| FP/帧 | 误检趋势 |
| 分机位通过率 | M 中景 / V 近景 / 远景（s29 类）分层，远景是预期薄弱层 |
| 检出召回（IoU≥0.5） | 微调模型质量监控 |

## 5. 指标分层：图片级 vs 视频级（口径澄清）

本方案是**视频识别**（逐帧检测 + 跨帧跟踪 + 片段判定），但内部可分三层，三层指标不可混用：

| 层 | 性质 | 是否需要连续帧 | 对应指标 | 当前已知值 |
|---|---|---|---|---|
| L1 检测 | 图片级：每帧独立推理，输出人框 | 否（单帧可算） | mAP50、单帧召回 | 裸模型 imgsz=1280：~11 人/帧；微调目标 mAP50 ≥ 0.90 |
| L2 跟踪 | 视频级：跨帧关联出稳定 ID | **是** | MOTA、IDF1、IDSW | 尚无（待 M3 管线跑通） |
| L3 判定 | 视频级：5 秒片段内 ≥85% 帧判对 | **是** | FrameAcc（达标线） | 尚无 |

要点：
1. **L1 单独达标 ≠ 最终达标**。L1 只保证"这一帧框对了"，不保证 ID 前后一致；帧判对同时要求检出 + ID 一致 + 误检受控。
2. 2026-10-18 的 yolo26n 裸模型探测（imgsz 640 vs 1280、conf 分布、目检图）**全部是 L1 图片级数据**，用途是定模型与分辨率，不能当成 L3 的 85% 来看。
3. 评测报告必须**分层给出**：先报 L1 召回/mAP，再报 L2 MOTA/IDF1/IDSW，最后报 L3 FrameAcc。这样未达标时能立刻定位是"检出问题"还是"ID 问题"（方案 A §6 的降级路径依赖这个区分）。
4. 端侧方案的 L2 是因果版（无未来帧），其 IDF1 天然低于方案 A，属预期差异，不是缺陷。

## 5b. 两方案评测差异

| | 方案 A 服务器 | 方案 B 端侧 |
|---|---|---|
| 被测对象 | 离线管线全链路 | 端侧部署形态（含 P 帧、兜底、int8） |
| 运行环境 | RTX 5070 Ti | 目标硬件或 PC NCNN 仿真（D1 阶段） |
| 附加报告 | 耗时/场 | 帧率分布、推理超时触发率、降档后精度损失 |
